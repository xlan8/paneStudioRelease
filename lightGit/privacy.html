Privacy Policy

Last updated: November 20, 2026 · Applies to all released versions of Light Git, including the Microsoft Store build and the direct-download build from the website

In one sentence: Light Git is a Git GUI that runs on your own computer. It has no account, no cloud sync and no ads, and it never uploads your code, commit history or repository addresses. The only statistics collected are anonymous usage analytics, whose scope is described in section 6.

1What this app does

Light Git is a Windows desktop program. It does not change your repository format; it simply calls the Git command-line tool already installed on your computer (git.exe) and a built-in Git library to do the work: viewing changes, committing, pushing, pulling, resolving conflicts, switching branches, creating tags and stashing. It also draws the results in a way that is easy to read.

So, apart from the Push / Pull / Clone actions you explicitly trigger — which connect to your own Git server — the app itself holds none of your data. We do not have your repositories, and we have no server storing your projects. The product has no such server at all.

2What the app stores on your computer

Everything the app produces is written to two directories on your machine and is never synced anywhere:

  • Repository list and current repository: which paths you have imported and which repository you last viewed, kept in the app's own WebView local storage.
  • Interface preferences: filters, sorting and grouping on the Changes page, column widths on the History page, plus language and theme choices.
  • settings.json: only two things — the detected path to git.exe, and whether that path was auto-detected or specified manually.
  • rating.json (Store build only): whether the rating prompt has been shown, whether you have permanently dismissed it, and the counters and timestamps used for timing.
  • update-state.json (direct-download build only): the result of the last update check, and the checksum and progress of the downloaded installer. The Store build does not check for updates and does not create this file.
  • LocalSettings (Store build only): a single flag recording whether we have already asked you to create a shortcut. It contains no shortcut location, disk path, usage count or anything that could identify you.
  • Portable Git (only if you click "Download Git"): when no Git installation is detected, the app unpacks a portable Git into its own data directory. It does not change the system PATH or write to the Windows Registry.

None of these files contains any repository content — no code, no commit history and no diff text. The app does not copy your repositories and does not make backups or caches of them.

Locations: %APPDATA%\com.lightgit.app (configuration and state) and %LOCALAPPDATA%\com.lightgit.app (WebView local storage). In the Store build these two directories live inside the app's own container and are removed with the app when it is uninstalled. In the direct-download build the uninstaller removes only the program itself; delete the two directories manually to clear everything.

3Where does your code go?

There is only one route: the remote address you enter yourself. During Push, Pull and Clone, data goes directly from your computer to GitHub, Gitee, GitLab or your company's own Git server — exactly as if you had typed git push on the command line. It does not pass through us. SSH mode uses the ssh client and keys already on your system; the app never reads, copies or uploads your private key.

Apart from the repository folders you import, the app does not scan other folders on your disk, and there is no "Auto-upload", "Cloud backup" or "Team sharing" entry anywhere in the interface.

4How are usernames and passwords handled?

When an HTTPS remote needs authentication, the app shows its own dialog asking for your username and password (or a personal access token). Once you confirm:

  • The credentials are handed to the system Git Credential Manager (which ultimately stores them in Windows Credential Manager), so they can be filled in automatically next time.
  • The app itself never writes a password file; there is no account list in Settings and no "saved passwords" entry.
  • These credentials are never sent to us and never enter the usage statistics.

To clear saved credentials, delete the corresponding Git entry under Windows Credential Manager → Windows Credentials, or change the remote address in Settings.

6Anonymous usage statistics

Released builds and this website collect anonymous usage statistics through Microsoft Clarity to learn which features get used, where new users get stuck, and which parts of the website people read before deciding. The direct-download build, the Microsoft Store build and this website use separate projects. No other third-party analytics and no crash reporting are integrated.

  • Collected: interface interactions and operation traces (including session replay and click heatmaps), app version, interface language, Windows version, screen size, and an approximate country/region inferred from IP. On the website, Clarity records page views, clicks, scrolling and the same approximate region; input fields are masked by default.
  • Not collected: your name, email address, account or anything else that identifies you; the app never reads or uploads files on your disk or repository content.
  • Not used for advertising, and never sold or shared with advertisers.

Clarity keeps a local identifier used only to distinguish sessions. The app has no accounts and does no cross-device identification. The collection, masking and retention rules are handled by Microsoft; see the Microsoft Privacy Statement.

There is no separate analytics toggle in the app. If you would rather not participate, you can add an outbound block rule for the app in Windows Firewall — apart from update checks and the one-click Git download, all other features run locally. On the website, you can opt out with a browser tracker blocker or by disabling JavaScript; the page content and all links remain available.

7What we explicitly do not do

  • No registration, no login, no account system and no "cloud workspace".
  • No reading of directories you have not imported, no uploading of repository content, and no code analysis or cloud builds.
  • No ads, no in-app purchases, and no prompts to install third-party programs.
  • No background rewriting of your repositories; if you do not click anything, it does nothing.
  • In the Microsoft Store build, creating a desktop shortcut or pinning to the taskbar happens only after you explicitly confirm. This feature collects no privacy data and never sends shortcut information to us. The pin-to-taskbar confirmation dialog is shown by Windows itself.
  • We never sell or hand data to any third party — apart from the four network scenarios listed above, there is no fifth.

8Data deletion

Uninstalling the app: in the Store build, app data lives in its own container and is deleted together with the app. In the direct-download build, after uninstalling, delete the two directories from section 2 to clear everything (they contain only paths, preferences and state — no repository content). After deletion, reinstalling starts fresh, as on first launch.

On our side, the usage statistics are only anonymous session records and do not point to any individual. If you would like certain records removed, email us with the approximate time and version and we will do our best to locate and delete the matching sessions.

9Minors

This app is a developer tool, is not designed for children, and collects no personally identifying information. Minors may use it under a guardian's guidance; no additional information is required.

10Policy updates

When features or network behavior change (for example, a new analytics provider or a different update source), we will update this page and its "Last updated" date; significant changes will be called out in the app's release notes. Continuing to use a newer version means you accept the updated policy.
